# Chest Evidence Agent

本地运行的胸部病例诊断辅助研究项目。输入病例文本和胸片，Agent 选择图像工具、检索资料，输出有证据引用的候选诊断，并在补充资料后重新判断。

这是基于 MedRAX 思路和 TorchXRayVision 图像工具的独立扩展，不是原论文指标复现。研究与学习用途，未经临床验证。

## 当前功能

- LangGraph：病例整理 → 分析计划 → 按需分类/分割 → 资料检索 → 临床证据对照 → 报告 → 证据复核 → 最多一次修订。
- 本地 Lingshu-32B NF4 医学视觉语言模型；保留Qwen对照，可切换 OpenAI 兼容 API 后端。
- DenseNet 胸片分类、PSPNet 肺/心脏分割与叠加图。分类分数不是患者患病概率；分割不提供虚构的物理单位。
- SQLite 保存病例、补充信息、本次输入快照、事件和报告。任务串行使用 GPU。
- 中文界面、执行进度、可点击证据、下载完整 JSON 记录。
- 三种对照模式：直接推理、工具分析、工具分析与证据复核。

## 本机启动

项目路径 `<project-directory>`。

```bash
cd <project-directory>
bash scripts/start.sh
```

远程访问当前常驻服务：**http://<server-ip>:7860**。这是本机验证时的LAN入口，使用时请替换为自己的服务器地址。当前通过一个轻量TCP入口转发到常驻模型服务，不重复加载GPU权重。

如果通过VS Code远程开发，可在底部「端口」面板添加 **7860**，然后点击「在浏览器中打开」。转发后使用面板显示的本地地址；远端的localhost不是用户电脑的localhost。首轮分析需要加载模型，耗时高于后续分析。

当前 `.venv` 使用 `--system-site-packages` 复用 `hest` 环境中的 PyTorch 2.11 + CUDA 13.0 和 Transformers，新增依赖安装到项目虚拟环境，不修改 `hest` 包。这不是完全独立的可移植环境；迁移机器时需要重新创建匹配 GPU 的环境。

模型路径默认 `../models/Lingshu-32B-NF4`，可通过 `CHEST_MODEL_PATH` 配置。默认权重来自固定版本的官方Lingshu-32B，由本机保存为NF4双重量化检查点，计算使用BF16，视觉模块与lm_head保留原精度。原Qwen3-VL-32B NF4权重保留用于对照。分类/分割权重默认由 TorchXRayVision 缓存到 `~/.torchxrayvision/models_data`。

```bash
# 新环境先安装适合 GPU 的 PyTorch/torchvision，再安装项目。
python -m pip install -e '.[dev]'
python scripts/prepare_data.py
python -m pytest -q
```

API 后端可配置 `CHEST_BACKEND=api`、`CHEST_API_MODEL`、`OPENAI_BASE_URL`、`OPENAI_API_KEY`。Key 不要写入版本库。

当前同时启用约245MB的胸片专用观察模型 `IAMJB/chexpert-mimic-cxr-findings-baseline`；通用视觉模型与它的输出都只是模型观察。专用模型报告中的设备、纵向比较和疾病解释分开保存，不作为已核实患者事实。可用 `CHEST_CXR_EXPERT=0` 关闭用于对照。

32B 默认输入上限8192 tokens，单任务串行运行；没有使用模型标称的超长上下文。不同输入的峰值显存仍需监控，显存记录包含 PyTorch 峰值以及测试脚本采样的整卡占用。

```bash
# 使用已有32B NF4权重需要量化依赖
.venv/bin/python -m pip install -e '.[quantized]'
# 旧8B模型保留，可以明确选择进行对照
CHEST_MODEL_PATH=../models/Qwen3-VL-8B-Instruct bash scripts/start.sh
```

JSON 处理现在拒绝用一个有效的内层候选对象冒充截断的完整报告。闭合报告中的括号语法错误可以修复，但修复前后字段、文字和数字必须一致，否则拒绝；随后仍通过严格的Pydantic结构校验。

## 数据与资料

`scripts/prepare_data.py` 获取 MedlinePlus 肺炎、心衰、胸膜疾病和肺孢子菌感染的公开摘要，并保留来源与抓取时间。目前是 TF-IDF 字符检索的小规模资料库，不是临床指南库或完整医学 RAG。

预置教学病例由 **人工编写病史 + MedRAX 官方样例胸片** 组成，它们不是同一个真实患者；仅测试流程，不能用于诊断准确率。样例图原始位置为 `../MedRAX/demo/chest/pneumonia1.jpg`。不要根据文件名判定诊断。

后续病例评测应使用有配套真实病史与参考诊断的数据。ChestAgentBench 主要是胸片选择题，应单独评测，不能把选择题准确率当作完整病例诊断准确率。

## 证据复核的范围

程序检查引用存在性、失败工具引用和患者自身证据是否缺失；模型复核检查事实编造与证据冲突。复核只能提供质量检查，不能证明诊断正确。修订后问题仍未解决时显示 `needs_review`，保留原始问题，不伪造通过状态。

任务进行时重启服务会标记为 `interrupted`，用户可重新提交；当前不是逐节点故障续跑。病例和已完成报告保留在数据库中。

## 评测

```bash
.venv/bin/python scripts/evaluate.py /path/to/curated_cases.json --output data/evaluation.json
```

输入 JSON 数组，每项包含 `title`、`context`、`image_path`（相对评测文件的路径）、`reference_diagnosis`，可选 `accepted_names`。参考诊断与别名只交给评分代码，不进入模型上下文。

记录任务完成、候选诊断名称匹配、耗时、模型/工具调用数和证据检查。名称匹配不是临床专家评分。新增按病例隔离的公开选择题抽样评测，方法与成绩单独记录，不能与开放诊断准确率混用。

小规模 ChestAgentBench 开发集可独立运行（不作为最终测试成绩）：

```bash
.venv/bin/python scripts/prepare_benchmark.py --limit 5
.venv/bin/python scripts/prepare_cases.py
.venv/bin/python scripts/evaluate.py data/benchmark/development.json --task multiple_choice
```

只选择单胸片、含诊断类别的题目，并按病例去重；标签仅在评分文件中，模型输入只含图像与题目。选择题得分不代表真实病例诊断能力。

`prepare_cases.py` 将公开病例的原始病史与匹配胸片配对，保存到界面及 `data/curated_development.json`。输入不含病例标题、最终诊断、病例讨论或已完成影像描述；参考结局仅写入评分文件。这些病例仍属于开发案例，且参考诊断可能依赖输入中未提供的其他检查，不能要求模型仅凭胸片确诊。

## 质量迭代

- 病例事实单独抽取：保存原文片段和证据ID；原文匹配与数字检查拒绝无依据的提取。
- 通用视觉模型与胸片专用模型各自观察；当前诊断、复核及修订阶段再次接收原图。CHEST_RECHECK_IMAGE=0 可恢复只使用工具观察的对照流程。
- 检索结合完整病史、候选检索词和医学同义词；筛除弱相关片段，控制同一来源数量。
- 资料库包含 MedlinePlus 健康资料、NIH 诊断指南摘要及有来源的专业诊断摘要。`scripts/expand_knowledge.py` 可准备扩展资料；NIH 直接下载被拒绝时，使用明确标识的公开来源摘要，不冒充抓取原文。
- 复核必须同时引用报告原句与证据原文；泛泛提醒、错误证据类型和无效引用不用于修订诊断。复核本身无效时保留未完成复核状态。
- 已提供检查不能再次列为缺失；去掉完全没有支持证据的鉴别项，不编造支持理由。
- 未新增资料时再次分析不会伪造“补充证据”；新增资料仅与上次输入快照比较。

## 按病例隔离的选择题评测

`scripts/prepare_independent_benchmark.py` 从本地 ChestAgentBench 原始文件中选择带诊断类别、仅使用一张胸片的题目。用配套元数据的图注确认胸片及初始检查，排除已用于开发的6个病例，固定随机种子20261007，从182个合格患者中抽取12个，每个患者保留一个题目。不是完整基准，也未排除预训练数据污染。

每题的输入只包含真实病史、对应图像与原始问题（含选项）。答案、最终诊断、图注与解释保留在评分端；题目自身可能包含临床线索，按原样保留。这种成绩不能当作开放诊断或临床准确率。

```bash
.venv/bin/python scripts/prepare_independent_benchmark.py
.venv/bin/python scripts/evaluate_http.py
.venv/bin/python scripts/export_error_review.py
```

通过已经运行的本地服务逐病例比较 `direct` 与 `verified`，避免再次加载32B模型。每种模式创建独立病例，不共享上一次报告。评测期间锁定流程、资料库与输入，保存SHA256指纹；模型答题错误和运行失败都保留在准确率分母中，任务完成率单独统计。选择题只按 `answer_choice` 与标准字母完全一致评分，不让同一个模型给自己打分。另记小样本Wilson区间与成对得失数。

中间结果写入 `data/independent/results.json`，记录待完成的服务任务，重复运行命令可续评。输入、流程、资料库或配置指纹改变时拒绝续评。`data/independent/error_review.json` 是仅供评价端使用的错误复查材料，分别保存原始观察、参考图注、选项与证据复核；人工批注不会被重新导出覆盖。错误来源未确定时留空，不能把名称相符或程序检查通过当成临床正确。

原图复看开关默认为开启；设置 `CHEST_RECHECK_IMAGE=0` 后重新启动可做只使用工具观察的消融对照。记录包含 `reasoning_reads_original_image`，只有诊断实际接收原图时才允许引用 `I-original`。复核和修订使用同一图像策略。

本轮新增测试验证原图确实传入诊断、复核与修订，以及评分时失败任务保留在分母、两种模式按患者配对。这些工程测试与模型诊断成绩分开记录。

### 结构化输出修复

本地生成默认启用 [LM Format Enforcer](https://github.com/noamgat/lm-format-enforcer) 的JSON Schema约束，同时保留Pydantic、引用与语义核对。选择题使用必须填写A–F字母的 `ChoiceReport`；开放病例仍使用允许 `answer_choice=null` 的普通报告。约束只限制输出结构，不保证医学正确，也不能将被token预算截断的报告自动补全。

`CHEST_CONSTRAINED_JSON=0` 可关闭本地解码约束；原图复看仍由独立开关控制。模型调用记录标记实际是否使用约束，健康接口显示当前开关。修改流程后应另存评测结果，不覆盖原成绩：

```bash
.venv/bin/python scripts/evaluate_http.py --output data/independent/results_constrained.json
```

上表尚未包含这次格式修复；本轮开发病例仅用于结构化输出回归，不是新的独立准确率成绩。当前47项工程测试通过，覆盖选择题必填字母、实际解码约束拒绝错误字段和超长鉴别列表，以及修订阶段保持选择题报告结构。


中文解码额外验证了真实Qwen分词器逐token允许“肺孢子菌肺炎；年龄：30岁”。JSON解析器在构造时使用分词器字符表，避免后续替换配置而未更新缓存字符表导致中文输出提前终止。失败回归记录保留在 `data/quality/structured_smoke_results.json`，修正后的回归另存为带 `_v2` 的记录，不替换失败历史。


结构化输出修复后的本机回归：同一个已有开发患者的直接选择题、完整Agent选择题及补充CD4/LDH后的开放诊断共3次运行均完成，全部模型调用实际启用了Schema约束；选择题不再漏填字母。显存和耗时见 `structured_output_validation.json`。这只是工程回归，不报告“100%诊断准确率”；新流程尚未重跑12例独立样本。


## 医学模型与工具验证实验
